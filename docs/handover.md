# Handover Prompt

## STEP 1 — Understand PRD

Baca dan pahami `PRD.md` secara menyeluruh.

Jangan langsung melakukan coding.

Setelah memahami PRD, buat breakdown project secara lengkap dari awal sampai selesai, meliputi:

* Phase
* Stage
* Step
* Feature
* Dependency
* Urutan pengerjaan
* Validation setiap tahap

Pastikan seluruh breakdown benar-benar berdasarkan isi `PRD.md` dan jangan menambahkan requirement yang tidak ada.

Berikan hasil breakdown secara lengkap agar dapat digunakan sebagai roadmap development.

**Kenapa:** PRD menjadi dasar untuk menentukan apa yang harus dibangun sebelum masuk ke tahap UI dan implementasi teknis.

---

## STEP 2 — Understand UI.md

Baca dan pahami `UI.md` secara menyeluruh.

Jangan melakukan coding terlebih dahulu.

Pahami seluruh guideline UI/UX yang tersedia, kemudian sesuaikan dengan breakdown dari `PRD.md`.

Identifikasi kebutuhan UI yang diperlukan untuk project, seperti:

* Page
* Layout
* Component
* Navigation
* Form
* Interaction
* Responsive behavior
* State UI

Jangan membuat design system atau style baru yang bertentangan dengan `UI.md`.

**Kenapa:** `UI.md` menjadi acuan utama agar seluruh frontend yang dibuat konsisten dengan design yang sudah ditentukan.

---

## STEP 3 — Understand README.md

Baca dan pahami `README.md` secara menyeluruh.

`README.md` merupakan project template StackPlus yang sudah disiapkan untuk project ini. Jangan mengubah atau mengganti architecture, technology stack, structure, workflow, atau configuration yang sudah ditentukan tanpa alasan dan konfirmasi.

Pahami seluruh isi README, terutama:

* Project structure
* Architecture
* Tech stack
* Frontend
* Backend
* Database
* Authentication
* API
* Development workflow
* Coding convention

Setelah memahami `PRD.md`, `UI.md`, dan `README.md`, gunakan ketiganya sebagai acuan utama untuk mengerjakan project sampai selesai.

**Kenapa:** PRD menentukan kebutuhan project, UI.md menentukan guideline frontend, dan README.md menentukan technical foundation project.

---

# RULES

* Selalu berpatokan pada `PRD.md`, `UI.md`, dan `README.md`.
* Selalu jawab dengan tepat dan jangan membuat asumsi yang tidak diketahui.
* Jika pekerjaan bisa dilakukan sekaligus, langsung kerjakan sebanyak yang diperlukan.
* Setiap jawaban berikan penjelasan singkat mengenai alasan pendekatan yang digunakan.
* **Jika ingin mengubah file/code yang sudah ada, selalu minta code aktual dari file tersebut terlebih dahulu. Jangan menebak atau mengasumsikan isi file.**
* Jika membuat file baru yang memang belum ada, boleh langsung membuat berdasarkan PRD, UI.md, dan README.md.
* Jangan mengubah architecture atau teknologi yang sudah ditentukan README tanpa konfirmasi.
* Jangan menambahkan feature atau requirement yang tidak ada di PRD tanpa konfirmasi.
